# SECURITY REPORT: ZAR-168

## Objective
Replace insecure pseudo-random generation of Robinhood broker reference/order IDs (`math/rand`) with cryptographically secure random generation (`crypto/rand`) to prevent predictability and potential collisions. Ensure the change gracefully handles entropy failures (failing closed).

## Scope
- `pkg/robinhood/mcp.go`: Modified random number generation.
- `pkg/robinhood/mcp_test.go`: Added test cases for entropy success and failure.

## Implementation Details
- Removed `math/rand` import.
- Added a package-level variable `var randReader io.Reader = crand.Reader` to allow injection of a mock deterministic reader in tests while utilizing `crypto/rand` securely in production.
- Refactored random ID generation in `ExecuteMCPOrder`:
  - `refID` now securely reads 16 bytes directly into a buffer using `io.ReadFull(randReader, buf)`.
  - Sub-order IDs generated on JSON decoding errors now read 6 bytes.
  - Standard order IDs read 4 bytes.
  - Format specifiers were updated to map directly to slices of the random byte buffers (e.g., `%x` formats output lengths deterministically based on the byte slice length without needing explicit padding limits like `%04x` mapping securely to exact bits).
- If `io.ReadFull` fails to read sufficient entropy (e.g., OS randomness depletion), the application cleanly fails closed by returning a wrapped `fmt.Errorf` detailing the secure generation error, preventing any predictable or default strings from being dispatched to the broker.

## Verification
- Code strictly limits the change scope and avoids modifications to actual order parameters or execution semantics.
- Deterministic test cases were added to `mcp_test.go` to ensure correctness without depending on timing loops or flakiness.
- Explicit tests were added to simulate entropy read failures in primary and fallback flows to verify that the application correctly fails closed.
- `gofmt -s -w` executed for quality.
- `go test -race ./pkg/robinhood/...` and `go test -race ./...` executed cleanly.
