# ZAR-169: Secure OAuth state token

## 🎯 What
The OAuth state token used in Robinhood MCP interactive authentication was previously generated predictably via a `time.Now().Unix()` timestamp, which is vulnerable to CSRF or replay style attacks in OAuth flows. We've changed it to generate 16 bytes of cryptographically secure random entropy using `crypto/rand` and encoded it with `base64.RawURLEncoding`.

## ⚠️ Risk
An attacker could predict the exact state token because the timestamp is easily guessable. The risk was mitigated since this flow happens locally on a 127.0.0.1 redirect server briefly for an interactive session, but replacing it guarantees unguessability according to the OAuth 2.0 BCP.

## 🛡️ Solution
1. In `pkg/robinhood/mcp.go`, introduced a `generateOAuthState()` helper to produce unguessable strings securely.
2. If `crand.Read` fails due to system entropy issues, the auth flow halts completely rather than falling back.
3. Added robust tests in `pkg/robinhood/mcp_test.go` ensuring states generated are different from one another, URL safe, and sufficiently lengthy.

## ✅ Verification
- Ran local unit test `go test -v ./pkg/robinhood/...` which passes.
- Ensures the URL safety, length check, and randomness of the new token state function works.
- Pre-commit verifications, including `go test -race ./...` and `go vet ./...`, completed locally showing no regression on existing PKCE logic or order handling.
