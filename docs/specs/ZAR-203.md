# 🧹 ZAR-203 Bounded Ticket Review Packets

## 🎯 What

Add a parent-built review-packet protocol to ticket delivery and Jules orchestration. Every initial, remediation-delta, and final independent/adversarial review receives actual diff evidence, named seams/tests, invariants, verification evidence, and prior remediation context.

## 💡 Why

Broad “review the complete diff” prompts caused reviewers to rediscover repository scope using broad file listings and searches. That inflated context/cache reads without improving acceptance rigor.

## ✅ Verification

Pre-review verification passed:

- `git diff --check` — exit 0.
- `go test -race ./...` — exit 0.
- `go vet ./...` — exit 0.
- `git status --short` — inspected; staged files are the ZAR-203 workflow/specification artifacts and the generated review packet is intentionally untracked under ignored `.pi/review-packets/`.

Initial independent review required explicit target-base/merge context and command-result evidence in the final packet. Initial adversarial review required every changed hunk and a merge-blocking result for unresolved evidence requests. The workflow and packet contract were remediated accordingly.

Final verification runs only after fresh final independent and adversarial reviews of this complete closeout diff are clean.
