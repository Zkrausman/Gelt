# Supplied-CSV actual-main dispatch conformance

Operators and assistants invoke the CLI entry point. Existing recurring CSV
tests exercise typed handlers and descriptor admission; their child helpers do
not invoke actual main. Private compiled delivery checks remain evidence for
their own candidates. These new tests make the main-to-handler connection a
recurring part of the Linux Go suite without adding a product command or format.

## Coverage and oracle

The fixed table covers twelve forms across eleven command names: diagnosis,
aligned three-family window comparison, reference/funded/fees/execution replay,
whole and selected-period BreakoutVol and TrendConfluence comparisons, and both
MeanReversion forms. Each valid invocation uses one owned 64-row flat strict CSV
with a space in its filename, distinct declared cash/cost tokens, and a valid
shared interval with its terminal sentinel. Values are synthetic, uncalibrated
declarations. No real data or operating case is selected.

Each actual-main child must equal its intended typed handler's complete stdout,
stderr and normal exit status for valid and missing-operand invocations. The
handler baseline shares production accounting: this is dispatch and argument
forwarding conformance, not an independent numerical or strategy oracle. Existing
accounting, original-OHLC and normalized-signal qualifications remain unchanged.
Distinct declarations help expose operand swaps without implementing new math.

Eleven unique command names also exercise sole `--help` precedence through main,
against source-defined detail help. Arity errors must be failures with no success
text or input-path/symbol echo. Two harmless non-whitelisted names are rejected
by the test helper before main. The total is 37 owned child invocations per
complete new conformance family: 24 data/arity, eleven help and two helper gates.

## Ownership and bounds

Only the test binary contains the helper. It accepts a closed list of existing
supplied-CSV command names; no legacy generated-data or operational command is
selected. Children use fresh disposable homes and a minimal explicit environment.
Input bytes are checked unchanged, unexpected home writes fail, and captured
UTF-8 outputs are checked against existing summary/help size bounds. This is
bounded trusted-fixture coverage, not isolation for arbitrary hostile code.

Children are waited; a generous watchdog bounds a broken test, and its expiry
always fails rather than counting as command acceptance. No command I/O deadline,
provider provenance, independent accounting truth, browser acceptance, trading,
qualification or operating admission is implied. Existing provider, privacy,
runtime and uncertain-operation boundaries remain intact.

## Changed files and required verification

`cmd/gelt/offline_main_dispatch_linux_test.go` adds the test-only table, closed
helper and subprocess assertions. This specification records the acceptance
boundary. No production dispatch, command output, API, calculation or input
admission changes.

Focused and full Go race/vet/build checks precede complete independent and
adversarial source/privacy review. A disposable exact-source negative control
substitutes harmless version output for one CSV dispatch and must fail the
corresponding conformance assertion. Canonical source is never mutated for that
control. Fresh required final-head Go/V2/scientific checks and ordinary draft
PR/exact-head CI/merge gates follow accepted final source reviews.

## Working verification

Focused race-enabled conformance, the complete Go race suite, vet, all-package
build and CLI build passed with isolated offline resources. Each complete
conformance run includes the 37 owned child invocations described above. The
canonical working source stayed unchanged during those checks.

The separate negative control changed only the disposable copy's
`backtest-causal` main branch to healthy version dispatch. The selected valid
case failed specifically with `stdout-match=false` while both the actual and
expected exits were 0. It was not a compilation, timeout or fixture failure.
The expected failing Go check exited 1; its child tree ended, and canonical
source bytes were verified unchanged. This distinguishes the new main-dispatch
oracle from a helper that merely calls the typed handler again.

Complete independent/adversarial source/privacy review and fresh required
final-head verification remain prerequisites to publication. These working
checks and the expected negative-control failure do not establish operating
qualification or recover any historical interrupted process.
