# ZAR-197: Shadow Trading Zero-Fake-Telemetry Boundary

## 🎯 What

Shadow strategy and plan evaluation now requires both a validated real quote plus all required timestamped provider indicators, and at least 60 validated provider-origin OHLCV bars. It rejects unavailable, malformed, non-finite, non-positive, out-of-range, stale, future-dated, unordered, and repeated/synthetic data. No indicator is used as a quote substitute.

The engine validates this boundary before strategy evaluation, trade creation, MTM, exits, session liquidations, cycle persistence, callback telemetry, or notifications. Invalid market data returns an error before any of those effects occur.

The current Robinhood MCP integration exposes timestamped technical-indicator results but not a historical OHLCV-series API. Therefore production fails closed rather than fabricating bars until a supported provider OHLCV capability is wired in. The test-only provider-bar seam supplies explicit, validated provenance for deterministic offline coverage.

## 💡 Why

Repeated closes/fixed volumes and synthetic fallback prices can generate fictitious signals, trades, exits, and shadow telemetry. Shadow records must not resemble live evidence without actual provider provenance.

## ✨ Result

Shadow evaluation is fail-closed at the complete market-data boundary. It cannot create live-equivalent telemetry from fabricated price or volume series.
